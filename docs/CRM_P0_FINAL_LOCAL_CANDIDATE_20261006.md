- Связанный клиент, выбранные товары, контакт и допустимый ответственный переходят из обращения в примерку. Ответственный переходит в заказ, если он присутствует в разрешённом списке; иначе остаётся текущий сотрудник. Период аренды из обращения сохранён, часовой пояс филиала показан явно.

## Границы и приёмка

- Автоматический перенос клиента относится к уже связанной карточке клиента. Для нового гостя создание/выбор карточки перед заказом остаётся необходимым действием.
- Проверка ошибок создания продажи не является новым полным sale fulfillment E2E. Полный сценарий продажи опирается на ранее принятый Core и существующий regression.
- Свежих физических iPhone/принтерных испытаний нет; PDF и Chrome не заменяют их. Исторические utilization/idle без полной истории парка остаются недоступны. Сайт/showroom, P1/P2 и новые интеграционные функции не развивались.
- Владелец принимает локальный кандидат по обычным рабочим сценариям. Перед публикацией обновлённой ветки нужно отдельное разрешение; текущий draft PR не содержит этих последних локальных коммитов.
- Production/main/live остаются за отдельным конкретным разрешением и прежним migration gate. Миграция `20261006150000_crm_p0_fittings`, SHA-256 `6978c759a2390115111ef2b1163ce9ebfccc526cd70f5b940a8e66c44bfb0adf`, в этом проходе не применялась.
