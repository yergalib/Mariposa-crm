## Что отправляется OpenAI

Проверено по реальной сборке payload `runAssistantConversation`, ограниченному schema и read-only tools:

| Данные | Отправка |
|---|---|
| Текущий текст и недавняя история | Да: максимум 9 сообщений, до 700 символов каждое; общий вход приложения ограничен. Сохранённая история может восстановить этот недавний контекст. Не вся CRM-история клиентов. |
| Параметры подбора | Да: даты/время, рост, размер, цвет, пожелания, категории, выбранные/недавние ID, cursor поиска; данные филиалов и часовой пояс. |
| Товары | Да, ограниченные текущие результаты разрешённых чтений: ID, название, исполнение/цвет, размеры/опции, цена, валюта и доступность на даты. Каталог целиком не выгружается. |
| Публичные контакты бизнеса | Да при запросе контактов: адрес, часы, публичный WhatsApp/ссылки шоурума. |
| Контакт в отдельной форме передачи | Нет в LLM payload: телефон/email сохраняется отдельным history/handoff API в Inquiry. Поле контакта не входит в schema AI-запроса или snapshot истории. |
| CRM-клиенты, их телефоны/имена, заказы, оплаты, сотрудники, себестоимость/маржа | Не читаются AI tools и не включаются приложением в payload. |
| Cookie, session/user/membership ID, пароли, env/ключи | Не включаются в модельный контекст. API-ключ используется серверным SDK как Authorization, никогда как текст модели/ответ браузеру. |
| Фото, документы, аудио | Бинарные файлы не отправляются этой текстовой цепочкой. Product images в UI не являются model inputs. |

**Ограничение свободного текста:** regex отклоняет распознаваемые телефоны/email/ссылки и фразы вроде «меня зовут», но не является гарантированным детектором любого имени или секрета. Например, отдельное «Анна» проходит. Поэтому нельзя обещать, что имя, вручную введённое в чат или записанное в названии товара, технически никогда не попадёт OpenAI. Не вводить имена, контакты, документы и секреты в AI-чат; контакт для обращения — только отдельное поле.

Семантический reviewer также получает предложенный ответ, последнее сообщение пользователя и параметры/пожелания. `store:false` и отсутствие SDK logging включены, но это не Zero Data Retention: официальная документация описывает стандартные abuse-monitoring logs до 30 дней и отдельное prompt caching. Настройки ZDR/добровольного data-sharing данного API-аккаунта не проверены. История и Inquiry сохраняются в текущем Supabase `ap-south-1`, не в новой KZ-инфраструктуре. Публичные HISTORY_OPEN/PUBLIC_INQUIRY_INTAKE_OPEN остаются false; этот пакет не открывает клиентский публичный intake.

## Тариф и точный общий лимит

Официальные страницы прочитаны 20.10.2026:

- https://developers.openai.com/api/docs/models/gpt-6-luna
- https://developers.openai.com/api/docs/guides/your-data

Standard, короткий контекст, USD за 1M tokens: input **0.10**, cached input **0.01**, cache write **0.125**, output **0.50**. Модель, standard tier, text-only, отсутствие hosted tools/parallel calls фиксируются сервером.

Резерв одного вызова: `(128768 × 0.125 / 1e6 + 1400 × 0.50 / 1e6) × 1.10 = $0.0184756`. Все input tokens консервативно оценены по наибольшей cache-write ставке. **100 × $0.0184756 = $1.84756**, ниже $2. Максимум 1 активная lease и 12 calls/min. Одна реплика может использовать до 4 provider calls, поэтому 100 calls не равны 100 ответам.

Проверочный endpoint `/api/showroom/assistant/smoke` делает **ровно один** фиксированный text request без каталога/контактов, output cap 64. Он использует тот же durable счётчик, тот же ключ, одну из 100 попыток и полный обычный резерв; повтор запрещён даже после reload/redeploy. Следовательно, после smoke остаётся максимум 99 calls. Никакой запрос этого endpoint в ходе подготовки не выполнялся против живого сайта.

Старая локальная история проверена: 284 attempts, резерв $5.2470704 из $6; незарезервировано $0.7529296. Неизвестный usage не возвращён в бюджет. Старое разовое разрешение истекло. Налоги/валютная конвертация конкретного платёжного аккаунта не установлены.

## Вход и непубличность

- Обычный CRM cookie host-only: существующая действующая MAIN OWNER-сессия на **том же Preview hostname** подходит. Новая сессия не нужна лишь ради AI.
- Если есть только login на production/другом hostname, требуется обычный вход на Preview. Если текущая сессия Pilot — обычный выбор MAIN/вход в MAIN. Переключение env не переключает организацию пользовательской сессии.
- Вход Vercel и CRM login — разные границы. Защита Vercel сохраняется, обходов и новых публичных разрешений нет.
- MAIN binding теперь сам включает ограничение чтения даже при удалённом/неверном флаге. До начала/после окончания дня MAIN остаётся закрыт, а не возвращается в публичный режим.
- Проверяется реальная getCurrentSession (активность user/org/membership, отзыв, expiry), точные org/membership/OWNER и CATALOG_VIEW. Handoff дополнительно требует LEAD_VIEW/LEAD_CREATE.
- Guard работает в SSR и центральном tenant() до query/storage reads. API ответы и owner-фото private/no-store; conditional photo request тоже проходит авторизацию перед 304. Каталог для владельца не зависит от доступности/ключа/бюджета модели.

## Записи и ограничения удаления

Создаются provider attempts; после согласия — Conversation/Message/quotas; после подтверждения — Inquiry/Items/INQUIRY_CREATED audit и ссылка истории. Никаких автоматических Customer/Order/Payment/stock writes от LLM. Контакт handoff остаётся только в CRM. Существующая модель хранит один активный consented conversation на browser capability + CRM session; после handoff запись неизменяема. В этом пакете удаление не разрешено, поэтому нельзя обещать неограниченное число новых сохраняемых диалогов в той же сессии. Несохранённые разговоры можно начинать заново в пределах call limit.

Истечение окна прекращает доступ/новые операции, **не удаляет** записи. Срок доступности истории 7 дней сам по себе не означает физическое удаление без retention job; job здесь не включается. Inquiry, заказ, финансовые записи и расходы OpenAI не исчезают от удаления чата. Любая дальнейшая адресная очистка — отдельное разрешение, не «обнуление всей базы».
